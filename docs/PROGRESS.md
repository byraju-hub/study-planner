## 실제 서비스로 확인하지 못한 것 (중요)
테스트는 **가짜 외부 서버**(`backend/tests/fake_external_server.php`, `fake_push_server.php`)로 했다. 아래는 코드가 있어도 실제 서비스와 맞는지 아직 모른다.
- **나이스**: `schoolInfo`·`hisTimetable` 요청 변수와 응답 필드 이름은 공개 안내를 기억해 구현했다. 인증키로 한 번 확인 필요. (`backend/src/Services/Neis.php`)
- **YES24**: `/v1/goods/itemList`(검색)와 `/v1/goods/content`(ISBN13 목차)는 개발자 문서(developers.yes24.com)를 보고 만들었다. 키로 실제 호출해 응답이 맞는지, 목차가 HTML·줄바꿈 중 어떤 형식인지, 호출 한도는 아직 확인하지 못했다. 약관상 YES24 출처 표기와 DB 대량 수집 금지를 지켜야 한다 (목차는 학생이 고친 단원 이름·쪽수만 저장).
- **Claude API**: 요청 형태(구조화 출력, 모델 `claude-haiku-5-5`)는 공식 문서 기준으로 만들었지만 실제 키로 호출해 보지 않았다. 모델 이름은 `config.php`의 `anthropic.model`로 바꾼다. PHP 공식 SDK 대신 curl을 쓴 것은 Cafe24에 의존성(composer)을 올리지 않으려는 선택이다.
- **웹 푸시**: 암호화·VAPID 서명은 독립 구현(Node `web-push`의 `http_ece`)으로 복호화·검증해 맞는 것을 확인했다. 하지만 실제 푸시 서비스(FCM 등)로 보내 휴대폰에 뜨는 것까지는 확인하지 못했다. iPhone은 홈 화면에 추가한 PWA에서만 동작.
- **크론**: Cafe24에서 외부(또는 호스팅) 크론이 호출 가능한지 확인 필요. 안 돼도 앱을 열 때마다 알림이 만들어진다(푸시는 못 받음).

## 구현하면서 정한 것 (설계 문서와 다른 점·세부)
- 복습 주기: 처음 공부한 날 다음 날 1차, 이후 3 → 7 → 14 → 30일. "어려웠어요"는 단계를 유지하고 내일 다시.
- 시험 대비 계획: 오늘부터 시험 **전날**까지를 1회독(약 60%) → 문제풀이 → 총정리(약 15%, 최소 하루)로 나눈다. 큰 범위는 "(1/4)"처럼 여러 날에 쪼개 빈 날이 없게 하고, 같은 과목·같은 날 범위는 할 일 하나로 합친다. 확정해도 이미 끝낸 할 일은 남기고 나머지만 교체한다. (`backend/src/Services/PlanService.php`)
- 수행평가 단계에 목표일을 정하면 그날 할 일(`tasks.source = 'assessment'`)이 만들어지고, 어느 쪽에서 체크해도 같이 바뀐다. 할 일을 지우면 단계의 목표일이 비워진다.
- 수행평가 경고: 마감이 시험 시작 7일 전 ~ 시험 종료일이면 표시한다.
- 시험·수행평가 계획 할 일은 모두 `sp_tasks` 테이블을 쓰고 `source`(study/exam/assessment/review)로 구분한다.
- 테이블 이름은 모두 `sp_` 접두어(Cafe24의 기존 DB에 같은 이름의 옛 테이블이 있어서).
- 날짜는 서버(Asia/Seoul) 기준. 화면은 서버가 준 날짜 문자열을 그대로 쓴다.

- 알림 규칙 세부: 아침 시각(기본 07:30) 이후 앱을 열거나 크론이 돌면 그날 요약이 만들어진다. 저녁 알림(기본 21:00)은 못 한 할 일이 있을 때만. 모든 알림은 `sp_notifications.dedupe_key`로 하루·항목당 한 번만 만든다.
- 관리자는 회원의 공부 내용·업로드 자료를 볼 수 없다. 회원 계정 관리만 한다.
- AI 문제는 학생이 쓴 노트(`note` 자료) 또는 붙여 넣은 글만 보낸다. 업로드 파일·교재 원문은 보내지 않는다.
- 퀴즈 통계는 문제마다 가장 최근 답만 센다. 한 번 틀렸어도 나중에 맞히면 "맞힌 문제".
- 새 마이그레이션의 FK 이름은 `sp_fk_...`로 시작한다 (005 이전 것은 `fk_...` 그대로).
